# Implementation Plan

Companion to `SPEC.md`. Each step is a self-contained unit of work for one agent.

## How to use this plan

- **Every agent reads `SPEC.md` and the "Shared contracts" section below before starting.**
- Do only your step. Don't refactor other modules; if a contract seems wrong, stop and report it
  rather than changing it.
- A step is done when every acceptance criterion passes and `pnpm check` (typecheck + oxlint + oxfmt --check + tests) is green.
- Run `pnpm format` before finishing a step.
- Keep dependencies minimal. The only runtime dependency allowed is `pdf-lib`.

## Tech choices (fixed)

| Concern | Choice | Why |
|---|---|---|
| Language | TypeScript, `strict: true` | Spec D11 |
| Build/dev server | Vite (vanilla-ts template) | Zero-config static output for GitHub Pages |
| Package manager | pnpm (pin via `packageManager` field + Corepack) | Nikhil's preference |
| Tests | Vitest | Native to Vite, fast |
| Lint | oxlint (`.oxlintrc.json`) | Nikhil's preference; no ESLint |

**Depends on:** S0

**Do:** Implement exactly the contracts above. Implement mulberry32:
```ts
let a = seed >>> 0;
return () => { a = (a + 0x6D2B79F5) >>> 0; let t = a;
  t = Math.imul(t ^ (t >>> 15), t | 1); t ^= t + Math.imul(t ^ (t >>> 7), t | 61);
  return ((t ^ (t >>> 14)) >>> 0) / 4294967296; };
```

**Tests:**

**Acceptance:** tests pass; no other module touched (beyond deleting the S0 placeholder test).

## S2 — Word bank build pipeline

**Depends on:** S0 (independent of S1)
**Files:** `scripts/build-words.ts`, `data/raw/*`, `data/exclude.txt`, `data/stopwords.txt`,
`data/blocklist.txt`, `data/SOURCES.md`, outputs `src/words/words.json`, `src/grid/blocklist.json`

**Do:**
1. **Source list.** Obtain a common-English frequency-ordered word list (top ~10k–20k words) with a
   licence that permits redistribution in a public repo. Candidates, in preference order:
   - `google-10000-english` (`google-10000-english-usa-no-swears.txt`); check its licence file.
   - The `wordfreq` English top-N list (data is CC BY-SA 4.0, so attribution is required).
   Commit the raw file under `data/raw/` and record source URL, licence, and retrieval date in
   `data/SOURCES.md`. **If neither licence is clearly OK, stop and report.**
2. **Stopwords.** `data/stopwords.txt`: function words (articles, pronouns, prepositions, conjunctions,
   auxiliaries like THE, WHICH, ABOUT, WOULD, THEIR, …) plus web/tech noise common in web-derived lists
   (HTML, ONLINE, EMAIL, LOGIN, …). One per line, uppercase.
3. **Blocklist.** `data/blocklist.txt`: profanity, slurs, and sensitive words (sexual, violent,
   drug-related). These are used **both** to remove words from the bank **and** by S5 to reject grids
   whose filler accidentally spells them. Include 3-letter entries here (S5 needs them), even
   though the bank's minimum length is 4. Also emit `src/grid/blocklist.json` (`string[]`, uppercase, deduped).
4. **`scripts/build-words.ts` pipeline**, applied in order, logging how many words each stage drops:
   1. Uppercase, trim, dedupe (keep first occurrence, which preserves frequency order).
   2. Keep only `/^[A-Z]+$/`.
   3. Keep length `MIN_WORD_LEN..MAX_WORD_LEN` (import constants from `src/core/types.ts`).
   4. Drop stopwords, blocklist entries, and anything in `exclude.txt`.
   5. Drop any word that *contains* a blocklist entry of length ≥ 4 as a substring.
   6. **Lemma collapse (heuristic):** iterating in frequency order and keeping a set of already-kept
      words, drop a word if a kept word equals its stem under any of these rules:
      `-S`, `-ES`, `-ED`, `-D`, `-ING`, `-ING`+`E` (MAKING→MAKE), doubled consonant + `-ED`/`-ING`
      (STOPPED→STOP), `-IES`→`Y`, `-IED`→`Y`, `-ER`, `-EST`, `-LY`. Also run the reverse check,
      so if a word's inflected form was kept first, the base form replaces it.
      (Simpler acceptable approach: two passes, first collect all, then keep the most frequent member of each stem group.)
   7. Take the first N survivors, where N = all survivors up to the 6,000th most frequent source word
      (tune so the result is roughly 1,500–3,000 words). Print the final count.
   8. Write `src/words/words.json` as a sorted `string[]`, with a 2-space-indented JSON array.
5. `data/exclude.txt`: seed it by running the script, skimming the output, and adding anything
   that's obscure, a proper noun, an abbreviation, brand/tech jargon (e.g. GOOGLE, PDF, DVD),
   or otherwise odd for a grandmother's puzzle. Re-run until clean. Keep one word per line, with
   `#` comments allowed and ignored by the script.
6. `src/words/bank.ts`: `export const WORD_BANK: readonly string[]` imported from `words.json`.

**Tests (`src/words/bank.test.ts`):**
- ≥ 1,500 words; all match `/^[A-Z]{4,12}$/`; no duplicates.
- No word is in the blocklist or contains a blocklist entry of length ≥ 4.
- Spot checks: contains common words (e.g. HOUSE, GARDEN, FAMILY, WINTER); doesn't contain
  HALCYON, THE, ABOUT, WALKED (if WALK present), HOUSES (if HOUSE present).

**Acceptance:** `pnpm build:words` is deterministic (re-running produces an identical file);
tests pass; `SOURCES.md` filled in. Report the final word count and paste 50 random sample words in the summary.

## S3 — Word selection for a batch

**Depends on:** S1. Use a fixture list in tests; at runtime it consumes `WORD_BANK`.
**Files:** `src/words/select.ts`, `src/words/select.test.ts`

**Interface:**
```ts
export interface WordPool {
  /** Draw a valid set of WORDS_PER_PUZZLE words, never returning a word used earlier in this pool. */
  drawSet(rng: Rng): string[];
  /** Return words from a failed puzzle attempt so they can be redrawn. */
  release(words: readonly string[]): void;
  remaining(): number;
}
export function createWordPool(bank: readonly string[]): WordPool;
export function wordsNeeded(puzzleCount: number): number; // puzzleCount * WORDS_PER_PUZZLE
```

**Rules for a set (all must hold):**
1. Exactly `WORDS_PER_PUZZLE` distinct words, none previously drawn from this pool (Spec D9).
2. **No containment:** no word in the set is a substring of another word in the set (HEART/HEARTH).
3. **Length mix, like the book:** at most 3 words of length ≥ 9; at least 4 words of length ≤ 6.
4. **Total letters ≤ 90** (so placement in 144 cells stays easy with modest overlap).

**Algorithm:** shuffle the remaining pool and greedily add words that keep rules 2–4 satisfiable;
if the greedy pass fails, reshuffle (max 50 tries), then throw `Error('Word pool exhausted')`.
Mark words as used only when `drawSet` returns. `release` puts them back.

**Tests:**
- 50 consecutive draws from a 1,500-word fixture → 600 distinct words, every set obeys rules 1–4.
- Deterministic for a given seed.
- Containment rule: a fixture containing HEART and HEARTH never yields both in one set.
- Throws a clear error when the pool can't satisfy a draw.
- `release` makes words drawable again.

## S4 — Grid placement

**Depends on:** S1
**Files:** `src/grid/place.ts`, `src/grid/place.test.ts`

**Interface:**
```ts
/** Cells are '' when empty. Returns null if it can't place all words within maxAttempts. */
export function placeWords(words: readonly string[], rng: Rng, maxAttempts?: number /* default 200 */):
  { grid: Grid; placements: Placement[] } | null;
export function cellsOf(p: Placement): Array<{ row: number; col: number }>;
```

**Algorithm (per attempt):**
1. Start with an empty `GRID_SIZE × GRID_SIZE` grid of `''`.
2. Order words longest-first (ties broken by RNG shuffle).
3. For each word, build all candidate `(row, col, dir)` positions where the word fits in bounds and every
   cell is empty or already holds the same letter. Shuffle the candidates with the RNG.
   - **Direction balance:** prefer the least-used direction so far. Sort candidates by
     (direction usage count asc, then shuffled order). The aim is a mix like the book's, not all horizontal.
   - **Mild overlap preference:** among equally ranked candidates, allow overlaps but don't seek them.
     (Don't over-engineer; overlaps just need to be permitted.)
   - Reject a candidate if its cells are a subset of an existing placement's cells, or vice versa.
4. Place the first valid candidate; if a word has no candidate, the attempt fails, so restart.
5. Return after the first successful attempt; `null` after `maxAttempts`.

**Tests:**
- For 200 random seeds and valid 12-word sets (use a fixed fixture of sets obeying S3's rules), placement
  succeeds and every placement's letters read back correctly from the grid.
- Only directions E, S, SE appear; all cells in bounds.
- Across 200 puzzles, each direction is used for ≥ 20% of placements.
- Overlapping cells always hold matching letters.
- Deterministic per seed.

## S5 — Filler and validation

**Depends on:** S1, S4 (uses `cellsOf` and the `placeWords` output shape)
**Files:** `src/grid/scan.ts`, `src/grid/fill.ts`, `src/grid/fill.test.ts`, `src/grid/scan.test.ts`

**Interfaces:**
```ts
// scan.ts
/** All occurrences of `word` reading in the allowed directions (E, S, SE) only. */
export function findOccurrences(grid: Grid, word: string): Placement[];
/** Every string of length minLen..maxLen readable in allowed directions. Used for the blocklist check. */
export function* readableStrings(grid: Grid, minLen: number, maxLen: number): Generator<string>;

// fill.ts
export function fillGrid(partial: Grid, rng: Rng): Grid;   // replaces '' with uniform random A–Z; returns new grid
export function validatePuzzle(grid: Grid, words: readonly string[], blocklist: ReadonlySet<string>):
  { ok: true } | { ok: false; reason: string };
/** fill + validate, retrying fill up to maxFills (default 50) times. null if never valid. */
export function fillAndValidate(partial: Grid, words: readonly string[], rng: Rng,
  blocklist: ReadonlySet<string>, maxFills?: number): Grid | null;
```

**Validation rules (Spec §4):**
1. Every grid cell is a single A–Z letter.
2. Every word has **exactly one** occurrence via `findOccurrences` (catches filler that spells a listed word again).
3. No blocklisted word is readable in the allowed directions **or in their reverses**
   (reverse too, because a solver scanning the page can spot rude words in any direction).
   Load the blocklist from `src/grid/blocklist.json`; tests may inject a small set.

**Tests:**
- Hand-built 12×12 grid fixtures: a word appearing twice fails rule 2; a word only readable reversed
  isn't counted as an occurrence; a blocklisted word reading backwards fails rule 3.
- `fillGrid` leaves placed letters untouched and fills every empty cell; across many fills, letter
  frequencies are roughly uniform (each letter 2–6% over 100k cells).
- `fillAndValidate` returns a valid grid for 200 seeds of S4 output.

## S6 — Batch generator

**Depends on:** S3, S4, S5
**Files:** `src/generate.ts`, `src/generate.test.ts`

**Interface:**
```ts
export interface GenerateOptions { count: number; seed?: number; bank?: readonly string[]; }
export function generatePuzzles(opts: GenerateOptions): Puzzle[];
```

**Algorithm:**
1. Validate `1 ≤ count ≤ MAX_PUZZLES` (throw otherwise). Seed defaults to `Date.now() >>> 0`.
   Bank defaults to `WORD_BANK`; blocklist from `blocklist.json`.
2. One RNG, one `WordPool` for the whole batch.
3. For each puzzle: `drawSet` → `placeWords` → `fillAndValidate`. On failure, `release` the words and
   retry with a fresh draw (max 20 tries per puzzle, then throw a descriptive error).
4. Return `Puzzle` with `words` sorted alphabetically.

**Tests:**
- `count: 50` succeeds, no word repeats across the batch, every puzzle passes `validatePuzzle`.
- Same seed → deep-equal output; different seed → different output.
- **Perf:** `count: 50` completes in < 2s in the test runner (spec budget is 5s end-to-end including PDF).
- Rejects `count` 0 and 51.

## S7 — PDF renderer

**Depends on:** S1 (types only), so it can be built in parallel using hand-made `Puzzle` fixtures.
**Files:** `src/pdf/render.ts`, `src/pdf/render.test.ts`

**Interface:**
```ts
export async function renderPdf(puzzles: readonly Puzzle[]): Promise<Uint8Array>;
```

**Layout (Spec §5), A4 portrait = 595.28 × 841.89 pt, origin bottom-left in pdf-lib:**
- Margins: 42.5 pt (15 mm) on all sides, giving a content width of 510.28 pt.
- **Grid:** full content width, cell = 510.28 / 12 ≈ 42.5 pt. Top edge at the top margin.
  Letters in **Helvetica**, size 28 pt, black, centred in each cell both horizontally
  (use `font.widthOfTextAtSize`) and vertically (baseline ≈ cell centre − 0.35 × fontSize).
  No cell borders, matching the book.
- **Rule:** 1 pt black line, full content width, 18 pt below the grid.
- **Word list:** starts 24 pt below the rule. Two columns (left column at the left margin, right column
  at the horizontal centre), 6 rows each, filled column-major from the alphabetical list.
  Helvetica 22 pt. Row pitch: divide the remaining height down to the bottom margin by 6, capped at 40 pt.
  Checkbox: an unfilled square (stroke 1.25 pt, side ≈ 0.6 × font size) drawn with `drawRectangle`,
  vertically centred on the text's x-height, with a gap of 0.4 × font size before the word.
  Don't use a ☐ glyph, because standard Helvetica (WinAnsi) can't encode it.
- One puzzle per page; no header, footer, or numbering.
- Set PDF metadata: title "Word Search", creator "Dadima Word Search Generator".
- Put all layout numbers in one exported `LAYOUT` constant object so S10 can tune them in one place.

**Tests:**
- `renderPdf([fixture])` returns bytes starting with `%PDF`; reloading via `PDFDocument.load` gives
  1 page of size A4 (±0.5 pt).
- 50 puzzles → 50 pages.
- Layout sanity (pure function test): export a `computeLayout()` helper and assert the word list's bottom
  ≥ the bottom margin and the grid fits within the content width.
- Also add a dev script `scripts/sample-pdf.ts` (`pnpm sample:pdf`) that writes `sample.pdf` from 3 fixture
  puzzles for visual inspection (gitignore `sample.pdf`).

## S10 — Verification and tuning

**Depends on:** S9. Run this with someone checking, ideally not the agent that wrote S7/S8.

**Do:**
1. Run `pnpm check`. Generate a 50-puzzle PDF and record the time taken (must be < 5s total).
2. Render 3 pages of the PDF to PNG (e.g. `pdftoppm -r 100`) and inspect them:
   letters centred in cells, nothing clipped, word list fits above the bottom margin, checkboxes aligned with text.
3. Programmatically re-verify a generated batch: for every puzzle, each listed word is found exactly once
   in E/S/SE directions; no repeats across the batch; no blocklisted strings in any of the 8 directions.
4. Skim 100 random words from the bank for anything unsuitable and add them to `exclude.txt` (re-run `build:words`).
5. **Human step (Nikhil / family):** print one page at home on A4 at "Actual size" (not "Fit to page").
   Confirm the letters are comfortably large and the grid spacing leaves room for pencil circles.
   Adjust the `LAYOUT` constants if needed.

**Acceptance:** a short `VERIFICATION.md` with results and the sample PNGs, plus any `LAYOUT` / `exclude.txt` changes made.
